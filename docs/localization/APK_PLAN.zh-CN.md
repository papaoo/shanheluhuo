## 交付目标

- 交付可安装、有稳定签名的 APK、SHA-256、安装和存档说明。
- 本地加载游戏及完整素材，首次断网可进入单机游戏；默认简体中文。
- 横屏优先；适配全屏、安全区域、返回键、后台保存/恢复、原生存档文件导出。
- 检查打包后实际内容，不能用源码或浏览器截图代替 APK 验收。
- 测量中文绘制与移动端运行，保留原性能阈值，实测仍超限时据实报告。

## 分工与边界

- 主代理：Android 配置、工具链、构建/签名、中文新增词条、最终 APK 安装与验收、交付文档。
- apk_assets：资源打包脚本和打包完整性检查；不改游戏/美术。
- apk_native：原生导出、生命周期、返回键与对应 Java/JS 桥接。
- apk_performance：性能证据与低风险优化、中文与离线复核；改动前报具体文件和原因。

保持游戏机制、AI、平衡、存档结构、原有美术模型与动画不变。保留原英俄语言选项和无关分析文档。原始项目的 16 项既有测试失败已有基线记录，不通过删除检查或调整玩法消除它们。

## 阶段和验收

1. 确认 SDK/JDK、设备或模拟器；建立本地资源构建，静态引用不得缺文件，动态字典必须完整。
2. 实现 Android 存档/生命周期，验证中文提示、取消操作、恢复与数据保留。
3. 构建测试 APK，在 Android 环境验证首启断网、新建游戏、中文、保存读取、后台恢复、导出文件和返回键。
4. 对打包后的游戏做性能检查与独立复核；正式签名产物校验签名和文件哈希，提供安装包及证据。

用户已明确要求适配大多数安卓手机，不针对单一机型。保留 Android 7.0 / API 24 最低安装版本，打包语法目标 Chrome 85，并为实际用到的新 API 提供兼容处理；以不同屏幕尺寸检查中文和操作。若没有连接真机，明确区分模拟器验证与真机帧率/发热/耗电结论。签名私钥及密码不进 Git、不写进报告；固定本次中文版应用 ID 和签名，以支持后续覆盖升级。
