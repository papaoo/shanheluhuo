# OldGold 简体中文本地化审计

日期：2026-11-15。基线：b1ec26d2f2eb7ff131a3fad7347bb5199d2090ac。
开发分支：feat/zh-cn-localization。本文为第 1 阶段只读审计结果；写入时尚未改动游戏代码。

## 目标与边界

增加独立的 zh-CN 语言及自然、统一的中文游戏文本，保留 ru/en、俄语源文本、英文词典、ID、玩法、存档结构和联机协议。覆盖本地浏览器游戏的 UI、建筑/商品/职业、英雄/装备/技能、任务/剧情、地牢、动态提示和存档界面。美术、机制重构与线上发布不在本轮范围。Android 安装包作为另行确认的交付范围；中文浏览器版验收不依赖该选择。

用户方案的技术路径可行；但翻译量不能归类为简单菜单汉化。现有 34 份英文词典合并后有 8,861 个唯一键，约 778,000 个序列化字符（俄文键和英文值合计）。提取器扫描到 10,348 条文本，其中 8,356 条精确命中英文键、1,992 条未精确命中；另有 505 个词典键未出现在静态提取结果中。扫描包含开发页、服务日志、旧文案及拼接片段，不能直接当作玩家文本总量或完成率分母。

## 现有语言系统

- js/i18n.js 以俄语原文为键，I18N.add('en', object) 装入英语，当前选择逻辑仅 ru/en。
- 优先级为 URL lang、localStorage.og_lang、浏览器语言；默认俄语浏览器用 ru，其余 en。
- 通过 document.write 同步加载 EN_FILES，保证游戏脚本使用词典前词典可用。没有构建器或模块打包要求。
- t(key, ...args) 支持 {0} 等参数；自动翻译还支持动态正则、大小写、别名、数字、标点及片段拼接。
- DOM setter、innerHTML、属性、MutationObserver、alert/confirm/prompt 与 Canvas fillText/strokeText/measureText 均有输出层包装。
- 俄语不安装翻译包装；语言切换自动保存已进入的游戏并刷新页面。
- 翻译数据不写入游戏状态；联机传输仍为原始字符串及 ID，每个客户端独立翻译。

## 需要改造的位置

1. LANGS、pick、locale、toggle 与 other 标签扩展为三语；中文识别 zh-CN/zh/zh-Hans。
2. 当前硬编码 I.dict.en 的所有查找路径改为当前语言词典；重建模式及缓存必须一致。
3. 中文词典独立放 js/i18n/zh-CN-*.js，与现有模块对应，额外缺漏放 zh-CN-extra.js。
4. 中文样式在原样式之后加载，仅作用于 html[lang="zh-CN"]，不改变原语言布局。
5. Canvas 设置中文字体回退，测量与绘制使用相同字体；按空格折行的 heroSay 等入口需要 CJK 折行。
6. Service Worker 需缓存中文文件，更新缓存版本；单页使用不能依赖在线字体服务。

## 提取与遗漏检测

现有工具 tools/i18n-extract.js 使用 Acorn 提取字符串字面量、模板、拼接及 HTML 文本；会重排占位符。loadDict 固定加载英语。tools/i18n/build.js 只生成四个早期英语词典，其占位符检查中的正则缺少反斜杠，不能用作中文质量门槛。

将保留原英语构建输入，另建中文检查工具：按实际运行时加载顺序统计词典，检查语法、键覆盖、重复/冲突、占位符、残留俄语和可疑英文，导出来源与未译报告。静态扫描与运行时 I18N.missing() 分开报告。

自动扫描无法独立保证：程序生成姓名/称号、分段拼接最终语序、聊天/玩家命名、字符串切片后的片段、Canvas 在翻译前折行、图像中的文字、未经过输出包装的外部页面，以及所有条件分支下的任务文案。需要真实游戏检查及定向用例。

## 字体与排版

现有 PT Serif/Kurale/Ruslan Display 不提供完整中文。优先采用系统 CJK 字体栈：Microsoft YaHei、PingFang SC、Noto Sans CJK SC/SC 等，避免引入大型字体和联网依赖。桌面和移动浏览器必须分别核查字体回退、measureText、对话长文本、按钮、库存及窄屏布局。不通过图片变更解决文字问题。

## 分工与验收

- 主代理：基线/术语、UI 与基础词典、遗漏工具、集成、实际浏览器验证和最终报告。
- 语言运行时代理：i18n.js、中文 CSS、语言框架测试；完成后参与其余翻译。
- 剧情代理：剧情/英雄/技能/竞技场/地牢词典。
- 世界代理：世界/经营/季节/装备/操作等词典。
- 互审重点：统一术语、俄文含义、占位符、动态语序、原语言回归、存档不变。

阶段顺序：审计 → 框架和术语 → 基础界面及内容 → 剧情高级系统 → 字体布局 → 全面验证。分阶段提交，只纳入本任务文件，保留现有未跟踪分析文档与 docs/交接.md。

验收包括 npm run check、npm test、中文专项静态/运行时测试及桌面/手机横屏浏览器检查。原基线已知合作测试在客户端 VM 加载 URLSearchParams 处失败，需要区分既有失败与本轮回归。历史视觉快照为俄英，不能用来直接判定中文画面像素相等；中文需独立场景检查。未验证部分和未译条目必须如实列出，不预先承诺 100%。
